# id, uid, vid and sid


📝 **You want just the least informations to use gdacm ? Just read the last paragraph** (What will you need to remember).

## Grafana Identifiers

Grafana defines two types of identifiers for dashboards and folders:
- **id**: a numeric identifier automatically assigned by Grafana and used internally.
- **uid**: a unique identifier for the dashboard, used in URLs and API calls.

You have no control over the `id` assigned by Grafana.

Grafana doesn't let you manually set the `uid` through the UI; it is automatically generated when you create a new dashboard or folder. But you can set it when create them through the API.

## gdacm Identifiers

Because **uid** are readable strings, and are used in URLs, it makes sense to choose meaningful values for them. ⚠️ But be carefull ⚠️ ! A uid should be unique within the Grafana instance. So using "my-dashboard" or "dashboard-health" is very likely to collide with existing uids once you work in an instance with multiple teams that doesn't corrdonate themself.

For that reason, every uid generated by gdacm will need a prefix that should be unique to your project or team. For example, your instance is used by multiple teams in multiple poles in your organization. You work in the team named "alpha" team, in the "r&d" pole. You could use a prefix like "pole-rd-alpha" as the prefix for your project.

If you manage several projects for your team, and the grafana instance is shared among multiple companies, if you work for ACME Corp, and work on project X and project Y you could use a prefix like "acme-pole-rd-alpha-x" for project X and "acme-pole-rd-alpha-y" for project Y.

Now comes the trick... A uid should not be longer than 40 characters in Grafana.

Thus, your uid should be long enough to be meaningful and unique within your Grafana instance, but short enough to not exceed the 40-character limit imposed by Grafana. To solve this, gdacm provides the concept of a **vid** (virtual uid).

A **vid** is basically a **uid**, but if the **vid** become longer than 40 characters, gdacm will use the 40 first characters of the sha-256 hash of the **vid** to generate a valid **uid** within Grafana's constraints. If the **vid** is 40 characters or shorter, it will be used as-is for the **uid**.

Thus you don't have to worry about the 40-character limit when generating meaningful and unique identifiers for your dashboards and folders. You can freely use long and descriptive **vid** values, and gdacm will ensure that the resulting **uid** is valid within Grafana. Just, when using long names, the url will be a bit less readable. Anyway, the uid can't be configured in the interface so in worst case scenarios, it will be as bad a "classical" dashboard.

The vid of your dashboard will be created using:
- Your project **vid** prefix
- A part part that come from the name of your folder if you put your dashboard inside a subfolder
- A part that come from the name of your dashboard itself

Those name parts are called in gdacm **sid** as "simple id"

## Examples

### Example 1: Dashboard in a Subfolder

So imagine you created a project with the **vid** prefix "acme-pole-rd-alpha-x" and a folder name "Health" with **sid** "health". You then put in that folder a dashboard named "Node status" with **sid** "node-status". The **vid** for this dashboard will be "acme-pole-rd-alpha-x-health-node-status". The length of that string is 39 characters. The **uid** will then be "acme-pole-rd-alpha-x-health-node-status".

- Project **vid** prefix: "acme-pole-rd-alpha-x"
- Folder **sid**: "health"
- Dashboard **sid**: "node-status"

- Dashboard **vid**: "acme-pole-rd-alpha-x-health-node-status"
- Dashboard **uid**: "acme-pole-rd-alpha-x-health-node-status"

You dashboard will be generated at URL : https://your-grafana-instance/d/acme-pole-rd-alpha-x-health-node-status/

### Example 2: Dashboard with a Long vid

So imagine now you created a project with the **vid** prefix "acme-pole-rd-alpha-x" and a folder name "Health" with **sid** "health". You then put in that folder a dashboard named "Node status with a very long name that exceeds forty characters" with **sid** "node-status-very-long-name". The **vid** for this dashboard will be "acme-pole-rd-alpha-x-health-node-status-very-long-name". The length of that string is 54 characters. The **uid** will then be the first 40 characters of the sha-256 hash thus "72b5f20c4539e93f90640db7b3153be4032eec4c"

- Project **vid** prefix: "acme-pole-rd-alpha-x"
- Folder **sid**: "health"
- Dashboard **sid**: "node-status-very-long-name"

- Dashboard **vid**: "acme-pole-rd-alpha-x-health-node-status-very-long-name"
- Dashboard **uid**: "72b5f20c4539e93f90640db7b3153be4032eec4c"

You dashboard will be generated at URL : https://your-grafana-instance/d/72b5f20c4539e93f90640db7b3153be4032eec4c/

The url is still deterministic (two generations of the same dashboard will result in the same dashboard uid, two different vid will result in different uids if you trust sha-256 algorithm) and you won't bother with uid management manually.

## What will you need to remember

- You need to provide a unique (inside the whole grafana instance) **vid** prefix for your project.
- You need to provide a unique (inside your project) **sid** for each folder within the project.
- You need to provide a unique (inside the folder) **sid** for each dashboard within a folder.
- When generating the dashboard a **uid** will automatically be provided to you be by gdacm, you won't need to bother at all how does works internally if you don't want to.
